# Prospective second-audit extension protocol

Created 2026-09-25 before the new pilot or measured execution. All workloads run only in Kubernetes context homelab, namespace trace-sampling-load-20260925, on homelab-01. Existing observations and freezes remain unchanged. This is a locally recorded protocol, not externally authenticated preregistration.

## Resource-load extension

The Collector remains pinned to Contrib v0.136.0. A synthetic OTLP/HTTP JSON source supplies five-span complete traces in groups of at most 100. Trace IDs are SHA256-derived from the runtime block, phase, and sequence. Every hundred traces contain one ERROR and one 400 ms root-duration trace; remaining durations are 10 ms. The pipeline exports uncompressed JSON to a file. There is no Jaeger in this extension. Application recording and generator CPU are outside the Collector boundary. The old live measurements retain those other boundaries.

A setup pilot sends full retention at 50, 2,000, and 8,000 traces/s. Pilot schedules use five seconds of warmup, five seconds of drain, ten seconds of measurement, and five seconds of final drain. The pilot selects load levels using execution feasibility and resource pressure, not sampling-policy effects: the highest measured level must use at least 0.25 CPU cores on average, have maximum scheduling lag below 0.5 s, and have no refusal, failed export, incomplete drain, or early tail drop. If 8,000 does not reach the CPU criterion, one additional 20,000-trace/s pilot is allowed. If an upper level cannot be delivered, preserve it and select the highest feasible tested level. Freeze the final level list and any necessary runtime correction before measured cells. No pilot observation enters the estimates.

The measured design crosses the final three or four rates with full retention, uniform deterministic head 10%, tail error/latency-plus-background nominal 10%, and retain-all tail. Head removes complete traces before ingress, so this extension measures a head gate, not SDK recording cost. Tail policies share order and salt, two-second wait, GOMAXPROCS=2, sample_on_first_match=false, and one common capacity equal to eight times the maximum selected trace rate plus 1,000. Decision caches are eight times that capacity. The batch processor uses a 1 s timeout, target 1,024 spans, maximum 2,048. Tail background probability is .08/.98; retain-all differs only in the background probability. Actual selected IDs, accepted/exported counts, batch counts, JSON bytes, CPU and RSS are retained.

Five randomized runtime blocks (62001-62005) each include every rate/policy combination. A fresh Collector runs per cell, with five seconds warmup and a five-second drain before the thirty-second measurement and common five-second final drain. The CPU endpoint precedes validation and compression. Raw process ticks, cgroup throttling, half-second RSS samples, metrics, send receipts, configs and compressed output spans are archived. Successful fixed-rate cells must reconcile all intended selections and counters, and stopping the process must add no output. Failed attempts remain archived. Report achieved schedule, raw CPU seconds, average core equivalents, CPU per offered span, output volumes and paired differences. All cells and contrasts are reported; no significance-based filtering. Five-block Student-t intervals are pointwise conditional runtime summaries. No capacity, production-fleet, monetary or saturation guarantee follows.

## Multi-trace diagnosis extension

The new task is localization of an injected duration change among three leaf services, motivated by healthy-reference comparisons in trace-based diagnosis. It is a deliberately simple fixed baseline, not an implementation of MicroRank or TraceRCA. Each incident has twenty healthy-reference and twenty incident requests. Each request visits all three leaf HTTP services; spans retain observed timings, identity and parent links, not injected-delay settings or cause labels. Leaf spans have no nested calls, so their observed durations do not inherit another service's work. A gateway span supplies request grouping.

There are 600 measured incidents, balanced across three target services, two added delays (5 and 15 ms), and two affected-request probabilities (0.5 and 1), with fifty independently seeded incidents per cell. Background service delays follow the same lognormal distribution with median 8 ms and log standard deviation 0.5. Injection choices and background draws are fixed by each incident seed. Execution order is randomized and at most eight incident workers execute concurrently. A separate twelve-incident setup pilot verifies execution and trace fields; correctness does not control acceptance and fault parameters cannot be tuned from pilot accuracy. Full-data errors remain in all reports.

For each service, the fixed scorer subtracts the median retained healthy-reference duration from the median retained incident duration and predicts the largest increase, even when all three differences are nonpositive. Service-name order breaks exact ties. If either window has zero retained complete requests, the scorer abstains. No required count above one is imposed. Scoring receives only observed spans, request-window grouping and candidate service names. It never receives injection settings, truth cause, sampling policy or original prediction.

The sampling policies for this diagnosis replay are ideal whole-trace Bernoulli head and protected tail with fresh uniform priorities. Protected traces have ERROR or root duration at least 80 ms; the achieved expected global trace budget is b=alpha+(1-alpha)r. These idealized replay policies isolate information loss and are not additional live Collector experiments. The protected fraction alpha is computed over the frozen measured corpus; budgets below alpha are infeasible and remain listed. Eight budgets are fixed: .05, .10, .20, .35, .50, .65, .80, .95. All rates, including unfavorable ones, are retained.

For each feasible policy/budget, 5,000 iid randomized replay trials draw one of the 600 fixed incidents uniformly with replacement and use fresh independent per-trace priorities. Trials are independent within a comparison under the declared ideal iid model for pseudorandom draws. Each trial initializes Python's random.Random with seed 990000 plus the trial number, draws an incident, then forty priorities; the same incident and priorities pair all comparisons. All random seeds and trial outcomes are retained. Full and sampled correctness, abstention, gains, losses, retained traces and spans are reported, including each workload stratum. Replay trials are not new incidents or deployments. The measured corpus contains only OK statuses, so this replay exercises latency protection, not ERROR protection.

Let Y indicate a full-data-correct diagnosis becoming incorrect or an abstention after sampling, and G the reverse. Conditional on the fixed corpus and replay policy, full accuracy minus expected sampled accuracy equals E[Y]-E[G], hence is at most E[Y]. One-sided exact binomial upper limits for E[Y] use alpha=.05/16 over the fixed family of sixteen policy/budget comparisons. Infeasible comparisons remain in that family size. A configuration meets the conditional five-percentage-point expected-loss objective only when its upper bound is at most .05. The zero-loss upper bound at n=5,000 is about .001153; at most 208 observed losses can meet the target. Near the margin the design may remain inconclusive. This is a simultaneous conditional randomized-replay bound on the fixed corpus, not a confidence statement about future production incidents. Report the baseline absolute accuracy so a weak baseline cannot hide behind relative preservation.

## Validation and reporting

Freeze source, scorer, policy, analysis, validator, final load levels and this protocol after setup checks and before measured execution. Archive all amendments and failed setup attempts. Separately implemented validators reconstruct selections, span structure/content, CPU endpoints, classifications, trial losses/gains and interval arithmetic without importing experiment/scorer functions. Corruption checks exercise rejection on disposable copies. Existing artifact validators and formal checks remain required. Final paper retains its main section order, author and template; it may narrow its title and research-question wording. Detailed historical verification and withdrawn-design material moves to the artifact, with concise disclosure in the paper. All sources, claims, figures, tables, references, PDF pages and cleanup receipts receive final checks.

The diagnosis measurement implementation uses explicit server-span timing around real HTTP leaf handling and a gateway request span. It does not reuse the SDK from the earlier live study and does not pass through a Collector: this experiment isolates retrospective evidence selection on observed application spans. All three candidate leaf services have no child calls. Root spans are excluded from the localization score. The reference and incident windows are both sampled. Random replay draws use shared priorities between policy/budget comparisons but fresh priorities across trials. Source and row fields distinguish truth, observed timings and predictions; truth is never supplied to the scorer. Before measured collection, an integrity check verifies that the archived spans reconstruct the timing records used by the scorer.
