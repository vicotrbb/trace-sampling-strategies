# Revision amendments and implementation decisions

## Before confirmatory execution

The original protocol remains unchanged. This log records refinements before confirmatory data are collected.

- Each application request contains five spans: gateway request, worker call, worker request, database query, and domain validation. Both applications execute real PostgreSQL operations. The error intervention is an undefined relation (SQLSTATE 42P01); the delay intervention executes a 350 ms query; the domain intervention changes the computed invoice or token count by one. Span attributes expose SQLSTATE, elapsed time, and domain invariants, but no injection label, control header, injected query text, incident ID, or truth lookup.
- The request schedule is 50 requests per second, with either uniform arrival spacing or the same 50 requests within the first 200 ms of each second. Confirmatory cells have a 10-second warmup, a five-second drain, 60 measured seconds, and a five-second drain. This is a finite-load experiment. It does not establish saturation capacity, a stationary production process, or storage maintenance over long time scales.
- Root IDs are the first 128 bits of SHA-256 applied to an opaque request identifier, itself derived from application, load, seed, phase and index. Fault assignment uses a separate random stream. The gateway does not accept an incoming trace parent. Actual SDK parent-based sampling propagates the root decision to the worker. Exact SDK selection will be independently checked against every ledger entry.
- PostgreSQL's complete container cgroup is measured through a loopback-only helper. Its cost includes the helper's own measurement work and PostgreSQL background processes. Application, Collector, and Jaeger process CPU are separately measured. PostgreSQL cgroup memory and process RSS use different accounting semantics and will not be added into a claimed physical-memory total.
- The file exporter is an additional evidence-collection sink in every policy. Its cost remains included in Collector measurements. Jaeger uses local Badger storage on an emptyDir; clean process-restart retrieval is tested, but node-crash, pod-deletion, and replicated storage durability are not tested.
- A prespecified offline partial-span ablation will remove (a) the gateway span, (b) the database span, (c) the domain-validation span, or (d) all but the relevant evidence leaf from full-retention measured traces. Predictions receive only the remaining spans. These interventions demonstrate sufficiency and necessity for the fixed scorer on the tested cases, not arbitrary future diagnosis.
- Offline rate curves will report both native SDK/FNV priorities and a separate common SHA-256 priority control. Native total tail budgets below the measured protected fraction are marked infeasible. The shared-priority control changes only policy, not hash implementation.
- Primary threshold certification concerns overall fault classification and constructed five-request group recovery, separately for each application/load combination and each of two policies over the ten prespecified rates: at most 160 comparisons. Report all block values. A simultaneous distribution-free one-sided Hoeffding bound across these comparisons is used under independent-block assumptions; with only five blocks it is deliberately conservative and cannot be replaced after observing results by a narrower unplanned test. Student-t intervals describe resource ratios and repeatability, not formal threshold certification. Deterministic full-retention equality is a control, not an inferred future guarantee.
- In the ablation where only the relevant leaf remains, the masking operation uses ground truth to choose which span to retain. This is an explicit intervention on evidence availability. The scorer receives neither the mask name nor the truth. It is not an online selection algorithm.

## Pilot acceptance and final freeze

Both pilots were kept separately: 12 original pilot cells and four backend-correction pilot cells. Independent reconstruction checked all exports, every request and span, propagated head decisions, raw before/after metrics, predictions, and backend content before and after clean restart. All cells passed; full-retention pilot protected fractions were exactly 0.02, all injected faults were correctly localized, and normal cases had no false accusation. The 50 requests/s schedule and fixed .08/.98 tail background are retained.

The first pilot exposed Jaeger internal tracing to an unused localhost endpoint. The documented Jaeger-only environment setting OTEL_TRACES_SAMPLER=always_off removes that activity; the OTLP receiver remains enabled. The second pilot also increases the Python HTTP listen backlog to 128. Neither change alters the classifier or fault predicates. No pilot observation is pooled into measured estimates.
