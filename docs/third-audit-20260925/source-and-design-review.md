# Source and design review

This internal review accompanies the new prospective extension. It is not external replication or peer review.

The window calculation follows directly by summing independent Bernoulli retention indicators. With w traces in each disjoint reference and incident window, expected retained counts are wp, and both windows are nonempty with probability [1-(1-p)^w]^2. This does not give a median-ranking accuracy formula. Noise, fault magnitude, affected fraction, and selection-dependent distributions remain part of the task.

The loss-event inequality and Clopper-Pearson inversion remain unchanged. Bonferroni allocation across 48 fixed configurations is valid despite dependence between nested windows and shared masks. The new bound is attainable: no more than 203 losses in 5,000 trials meet the five-point margin, and the zero-loss bound is 0.00137244. The prospective numerical receipt records those values and the probability of passing for several true loss-event rates. This power calculation concerns loss events, not net loss. Ignoring gains is deliberately conservative; more trials do not remove that difference in endpoints. The initial 16-comparison result remains a separate family, not pooled or retroactively reanalyzed to improve its conclusion.

The calibrated policy is fixed before measured incidents and uses a nearest-rank healthy-root 95th percentile, with disjoint calibration seeds. It has no access to fault labels. Protected mass is calculated over each measured prefix corpus only to equalize the expected global budget under the declared ideal replay law. This is an offline comparison, not a deployable guarantee of a known future protected fraction. Infeasible budgets remain represented in the comparison family.

The official Collector Contrib v0.136.0 source was retrieved from the OpenTelemetry repository on 2026-09-25. The archive includes `fnvhasher.go`, `sampler_mode.go`, and the processor README in `sources/`. The two uniform controls explicitly select `mode: hash_seed`, avoiding ambiguity in documentation about defaults. `computeHash` prepends the little-endian 32-bit seed to the trace ID and uses FNV-1a32. Its 14-bit bucket is compared with floor(10 * 16384 / 100)=1638. The source's equivalent 56-bit representation explains the native tracestate randomness and threshold fields. The separate validator reconstructs both selected IDs and this added metadata.

The uniform gate and native processor select identical IDs, verified on the excluded functional pilot. Native processing also inserts sampling metadata. Their CPU and byte contrasts therefore include ingress placement, processor work, and metadata handling; they do not identify a pure ingestion coefficient. The tail comparison retains its different protected/background decision rule and may retain different content. All resource estimates retain the complete Collector plus JSON-export boundary.

Existing attributions in `paper/intro-related.tex` retain the scope verified in `docs/second-audit-20260925/final-source-check.md`. The new citation concerns the pinned implementation directly read here. The proof appendix now also proves the window-availability calculation. No new claim about competitive sampler superiority is introduced. The published spelling Coehlo is retained.

The aggregate statistical families, corpus incidents, nested configurations, replay trials, and runtime blocks are distinct units in the manuscript. The new experiments run sequentially in the homelab. Local computations only check and analyze the archived evidence.
