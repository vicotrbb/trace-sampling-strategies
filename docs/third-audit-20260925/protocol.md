## Window size and calibrated tail policy

Collect 600 NEW incidents: three affected services by added delay 5/15 ms by affected-request probability 0.5/1, fifty seeds per combination. Each incident has 200 reference and 200 incident requests. Each request visits all three real loopback HTTP leaf servers sequentially. Background delay draws remain lognormal with median 8 ms and log standard deviation 0.5. At most eight incident workers run concurrently. The injected controls remain outside the observed four-span traces. All full-data errors are retained. The observed delays include server scheduling overhead. No SDK or Collector participates in this information-selection experiment.

Use nested prefixes of 20, 50, and 200 requests in EACH window. Thus 600 independent seeded episodes supply 1,800 dependent window configurations, not 1,800 independent incidents. Prefixes preserve request order. The earlier 600 incidents are a separate historical corpus, not pooled. Scoring remains the largest leaf median increase, ordinary even-count median, alphabetical service tie-breaking, and abstention only when either retained window is empty. Compute the full-data baseline separately at each size. Changes across sizes also change the baseline's accuracy; report absolute accuracy as well as relative deterioration.

Before incident measurement, collect 2,000 separate healthy requests in fifty 20+20-request episodes with disjoint seeds and the same generator/worker settings. Choose the tail protection threshold as the 1,900th smallest observed root duration (nearest-rank empirical healthy 95th percentile). Record and freeze the threshold before collecting the measured incidents. This comparison concerns root duration, not the leaf's 8 ms delay median. Preserve all calibration observations. A twelve-incident, twenty-request-per-window functional pilot is excluded; its accuracy cannot change workload, scorer, window sizes, threshold rule, or budgets. A pilot may correct execution or validation defects, recorded in amendments, before measured execution.

Both reference and incident traces are selected. Compare ideal Bernoulli head to ideal tail protecting roots at least the calibrated threshold, with budgets .05, .10, .20, .35, .50, .65, .80, .95. For each window size compute its protected mass over the entire fixed corpus, then background r=(b-alpha)/(1-alpha). This global expected trace budget gives protection to slow observed roots without consulting cause labels. All statuses are OK. Budgets below alpha are infeasible; keep their rows and do not substitute a different rule. Calibrating on healthy data does not imply exactly 5% protection in incident data, nor does protection imply diagnostic utility. No result-dependent threshold changes are permitted.

Run exactly 5,000 replay trials. Each trial uses Random(1990000+trial), uniformly draws one of the 600 incidents with replacement, then draws 400 priorities. Share that incident and its per-trace priorities across all 48 comparisons; nested prefixes share priorities for the same actual traces. Fresh trial streams instantiate the ideal iid model. Archive every row, including infeasible comparisons, retained reference/incident counts, baseline/sample predictions, losses, gains, and abstentions. PRNG determinism does not itself establish independence; coverage remains conditional on the ideal model and fixed corpus.

Primary inference retains the previously declared loss-only method. For Y=B(1-A), G=(1-B)A, net expected deterioration is E[Y]-E[G] <= E[Y]. A one-sided Clopper-Pearson upper limit for Y uses error probability .05/48. Shared comparisons and nested windows do not invalidate the union bound. All 48 configurations count toward this family, including infeasible budgets. Declare a tested rate supported only if its bound is <=.05; otherwise report inconclusive. Report the full 2x2 outcome counts, gains, net paired loss, absolute accuracy, expected/observed retained counts, and descriptive workload strata. No continuous retention threshold or per-stratum coverage is asserted. The earlier sixteen-comparison inference remains its own historical family and is not pooled. No new gain-aware passing rule will be selected after outcomes. The loss-only choice gives simple finite-sample coverage without assumptions of monotone scoring or a perfect baseline, at the explicit cost of ignoring compensating gains.

## Collector ingestion-boundary control

At 100,000 offered spans/s before any selection, repeat five randomized blocks of four fresh-Collector treatments: full bypass, pre-ingress uniform gate, Collector-side probabilistic sampler, and tail error/latency-plus-background nominal 10%. New block IDs 72001-72005 provide independent runtime repeats of this configuration, not new deployments. Use complete five-span traces, the same input batches of at most 100 traces, five-second warmup, five-second drain, thirty-second measured load and five-second final drain. Tail's settings match the prior high-load configuration, with 161,000 trace slots and eight times that many entries in each decision cache, a two-second wait, and nominal protected fraction .02. JSON file export, GOMAXPROCS=2 and batch timeout 1,000 ms/target 1,024/maximum 2,048 are common.

The two uniform controls use EXACTLY the same selected trace IDs: pinned Collector v0.136.0 hash_seed mode, seed 1729, configured 10%, 14-bit FNV-1a buckets with acceptance bucket<1638. The pre-ingress gate independently implements that decision. Effective ideal bucket fraction is 1638/16384, approximately 9.9976%. Collector-side sampling receives all spans and precedes batching. It also adds native sampling tracestate metadata, which must be retained and disclosed; therefore the gate-versus-processor contrast includes processing and metadata overhead as well as avoided ingestion, not a pure identified ingestion coefficient. The tail arm uses the original FNV-1a64 salt and background rule and selects a different set. None of these controls measure SDK recording savings. The prior BLAKE2b gate's 82.2% remains a separate historical result.

A functional pilot runs all four policies at 2,000 traces/s with five measured seconds, excluded from estimates. Parameters cannot be tuned to obtain favorable CPU directions. All measured cells must reconcile exact selections, span content and completeness, accepted/exported counters, and fixed endpoint drain; retain failed attempts. Report schedule lag and throttling rather than silently discarding high-cost cells. Archive process CPU ticks, RSS samples, metrics, configurations, outputs and source hashes. Analyze all five paired runtime blocks with descriptive pointwise Student-t intervals; no multiple-comparison significance claims. Diagnosis/calibration/replay and load measurements never overlap on the runner. Inspect every comparison even when its direction differs from expectations.
