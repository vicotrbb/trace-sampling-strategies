## Mathematical review

| Argument | Assessment and required qualification |
|---|---|
| Independent whole-trace binomial recovery | Correct for fixed distinct witnesses, fixed k, and independent Bernoulli inclusion. A deterministic hash implementation matching its own specification does not prove the randomness assumptions. |
| Threshold inversion | Correct for m >= 1, 1 <= k <= m, and 0 < delta < 1. The derivative is positive on (0,1), including k=1 and k=m; endpoint values establish existence and uniqueness. |
| Disjoint evidence types | Product is correct only for disjoint trace sets and independent decisions. Shared witnesses or correlated selection require joint probabilities. |
| Poisson arrival model | Correct for nonnegative rate/time and independent thinning. A mean arrival rate does not establish Poisson arrivals. Its full-retention baseline can fail because no witness arrives. |
| Protected/background tail | Correct for a fixed protected subset, complete observations, and expected cardinality budget b >= alpha. The strict comparison for unprotected witnesses requires alpha>0 and b<1. Trace-budget matching is not byte-budget matching. |
| Mixed protected witnesses | Correct shifted-binomial result. A marginal classifier sensitivity alone does not justify independent classification across witnesses. |
| Downstream loss | Correct for subset selection and a monotone predicate. The independent-stage product and shared-uniform minimum counterexample are correct. |
| Singleton bound | Add **N >= 1** to the theorem. Averaging the inclusion probabilities then proves that at least one is at most b. There is no singleton in an empty population. |
| Independent-sampling impossibility | State 0 <= p < 1 and quantification over **arbitrarily large finite populations/evidence requirements**. For any fixed such p, a sufficiently large all-d-indispensable task has p^d < .95. This is not an impossibility theorem for every task in a fixed finite population. |
| Expected-budget minimax | Correct for a nonempty finite population, b in [0,1], monotone Boolean predicates and D(T)=1. Requiring all traces gives the upper bound; keep-all with probability b attains the lower bound. A hard cap below N changes the result. |
| Additive bytes and Horvitz-Thompson | Correct with fixed additive trace values and known positive inclusion probabilities. Horvitz-Thompson unbiasedness does not require independent inclusion, but does require the actual inclusion probabilities and an appropriate observation model. |
| Conditional cost and occupancy | Subtraction is correct under the stated linear-cost decomposition. Neither this identity nor mean occupancy lambda W proves measured capacity, peak memory, compaction cost, or monetary savings. |

The Lean source proves the advertised discrete core. It does not formalize real probabilities, confidence coverage, the SDK/Collector, or diagnostic classifier correctness. Retain that boundary.

An important new boundary is that classifier correctness need not be monotone in the available spans. Extra ambiguous evidence can change a classifier's answer. Let C denote complete-witness recovery and A denote correct cause-and-service classification. In general, P(A) = P(A|C)P(C) + P(A|not C)P(not C). The conditional terms can change with policy and rate. The binomial formula for P(C) is therefore not automatically a formula for P(A). A lower bound P(A)>=P(C) requires a pointwise sufficiency argument for the fixed classifier, not merely high observed agreement.

## Diagnostic endpoint and RQ4

1. **Separate the classifier from the injector.** Freeze and hash classifier code before confirmatory observations. Supply only retrieved trace content and a neutral task/request identifier. Exclude truth labels, injection headers, identifying route/query names, run-order codes, and out-of-band failure schedules. A classifier may use ordinary SQLSTATE, service identity, measured durations, and domain fields that would normally be instrumented. Injection-specific query strings such as a literal `pg_sleep` command can become shortcuts; either sanitize them or explicitly acknowledge the artificially recognizable task.
2. **State what counts as a case.** Prefer prespecified live fault episodes plus prescheduled normal episodes if the paper claims incident diagnosis. Record offered requests, completed requests, retries, and actual affected request counts for each episode. Offline grouping of unrelated requests can remain a separate witness experiment, but does not become a live incident merely because the spans came from an application.
3. **Keep failures in the denominator.** Missing traces, empty retrieval, abstentions, wrong service, and wrong cause must be distinct scored outcomes. Include healthy cases to quantify false diagnoses. Report complete cause-and-service accuracy, cause accuracy, localization accuracy, abstention/missing rates, and a confusion matrix. Do not quietly restrict primary accuracy to retained or fully observed traces.
4. **Validate the witness proxy directly.** Cross-tabulate C and A, including useful incomplete traces and complete but incorrectly diagnosed traces. If normal head/full outputs remain complete, add a clearly labeled offline span-ablation experiment on held-out full traces, with prespecified masking patterns. Do not pretend whole-trace thinning tests tolerance to incomplete traces.
5. **Use an independent full-retention baseline.** Report its actual diagnostic accuracy, including unexpected application errors and instrumentation failures. A separately reported conditional analysis of cases diagnosable at full retention is useful, but it must not replace the unconditional endpoint or silently remove hard cases.
6. **Define material deterioration prospectively.** A defensible operational criterion is a chosen absolute loss margin Delta in diagnosis success relative to full retention, with a lower confidence bound on success difference exceeding -Delta. For example, a five-percentage-point margin is a possible declared engineering requirement, not an empirically discovered constant. An additional absolute success requirement may be appropriate. A nonsignificant difference from full retention is not evidence of noninferiority. The need to prespecify practically meaningful bounds follows the equivalence-testing literature; the exact paired-binary procedure must match the case/cluster design. [Lakens 2017, original article](https://pure.tue.nl/ws/portalfiles/portal/80918653/lakeequi2017.pdf).

Three online policies at full and 10% retention establish two sampled comparisons, not a complete deterioration threshold. Offline rate curves can estimate selection sensitivity on the observed full-trace corpus. Label them as conditional offline results. They cannot establish application overhead, buffer effects, backend capacity, or an end-to-end operational threshold. If selecting the largest passing discard level from a grid, use simultaneous bounds or a separate held-out validation stage; otherwise selection over rates makes a nominal pointwise bound optimistic.

## Sampling implementation and budget checks

The SDK head configuration must make a genuine root decision. `ParentBased(TraceIdRatioBased(.1))` uses the root sampler only when there is no parent; an incoming sampled `traceparent` from the load generator can cause it to retain all requests. Generate gateway roots with the SDK's ID generator, or a documented pinned generator, then propagate the decision downstream. Keep request-to-trace linkage out of band. Verify exact root decisions, propagation, and absence of independently sampled orphan descendants against the pinned SDK source. [Official Python SDK sampler documentation](https://opentelemetry-python.readthedocs.io/en/latest/sdk/trace.sampling.html).

The proposed 10% tail target is feasible with retain-all-protected only when alpha<=.10. Actual SQL delays, queueing and unrelated slow healthy requests can increase alpha. Do not assume the original synthetic value .02. An independent pilot can set a frozen background rate and latency threshold, followed by reporting actual protected/retained fractions per cell. Call this a target budget if matching is approximate. Do not retrospectively tune r using confirmatory outcomes and describe the design as prespecified. Exact fixed-corpus matching is possible offline using r=(b-alpha)/(1-alpha); this is a different estimand. A byte-budget comparison should use measured bytes, not an assumed trace-to-byte conversion.

For policy-only comparisons, use one shared random priority U per trace: head keeps U<b, and tail keeps protected traces or U<r. The resulting head/tail outcomes are intentionally paired and dependent; this controls random-priority variation. It does not reproduce the native SDK and FNV implementations simultaneously. Keep native end-to-end measurements and shared-priority offline comparisons distinct. A fixed native hash salt plus many traces is one implementation configuration, not many independently randomized hash functions.

## Calibration follow-up

Retain the original 19/100 semantic m=5 result versus 34.6746% predicted. Its exact implementation agreement excludes unexplained output loss but does not validate Bernoulli calibration. The supplied audit reports a retrospective two-sided binomial p near .000715 across a setting with 130 nondegenerate comparisons. It would not pass the simple .05/130 Bonferroni cutoff. That does not establish either calibration or bias, and it is not a prespecified global test.

For new evidence, freeze a finite calibration matrix including ID generator, independent generator seed, hash/salt, rates, witness multiplicity, and grouping. Separate the random streams used for IDs, workload ordering, fault placement and salts. Include the originally discrepant stratum and report all prespecified cells. Independently reproduce threshold rounding and inclusive/exclusive comparison semantics before comparing outputs with ideal probabilities. Use fresh data; do not pool the selected historical discrepancy into an ostensibly confirmatory test.

Prespecify valid marginal tests and control their family, for example with Holm's step-down procedure. Its familywise protection permits dependence between tests, but does not repair invalid marginal p-values or prove hash independence. If claiming an omnibus result, state the combined null and rejection rule explicitly. Publish effect sizes and uncertainty as well as adjusted p-values. Failure to reject a calibration null is not evidence of exact calibration; state what deviation the sample can rule out. [Holm 1979, original paper](https://www.ime.usp.br/~abe/lista/pdf4R8xPVzCnX.pdf).

## Resource measurements and statistical units

The proposed 2 applications x 2 loads x 3 policies x 5 blocks is 60 online cells. Randomize policy order within each application/load/block and spread blocks across time periods if feasible. Block on comparable nuisance conditions. Pair comparisons within those blocks and publish each block value. [NIST randomized-block design guidance](https://www.itl.nist.gov/div898/handbook/pri/section3/pri332.htm), [NIST paired-observation analysis](https://www.itl.nist.gov/div898/handbook/prc/section3/prc311.htm).

Five blocks remain a small replication count for system variability. More requests within a run improve a conditional sampling estimate but do not create more independent runtime environments. Cases sharing a fault episode or run can be dependent. Choose the inferential unit from the actual randomization and common causes; avoid ordinary binomial intervals on correlated episode outcomes or a naive trace-level bootstrap. A bootstrap over only five run clusters is not a universal remedy. With a simple paired two-sided sign-flip test and only five independent pairs, the minimum attainable two-sided p-value is 2/32=.0625. Report estimation and limited repeatability honestly rather than promising arbitrary precision.

Use these measurement boundaries:

- Include gateway and downstream application processes, PostgreSQL's full process tree/cgroup, Collector, and Jaeger/Badger. If any are omitted, name the measured subset. Report load-generator work separately.
- Save synchronized start/end counter snapshots, monotonic timestamps, process start times, and per-cell source/configuration/image hashes. Record restarts and cgroup CPU throttling, not just process CPU ticks.
- Sum nonoverlapping CPU consumption over one common interval. For total memory use synchronized observations; the sum of component peaks at different times is not the stack's simultaneous peak. Distinguish process RSS from cgroup memory/cache accounting.
- Preserve offered and achieved throughput, schedule lag, response latency/errors, and completed operations. An overloaded policy that performs less application work can appear cheaper. Report both total consumption and clearly defined per-offered/per-completed-request quantities.
- Prespecify warmup, load and drain windows. Drain late spans before reconciliation and measure its cost consistently. Run retrieval/classification after resource endpoints unless query cost is an explicit measured treatment. Sixty seconds improves the original run length but does not establish steady-state compaction, retention or capacity by itself.
- Configure Badger with `ephemeral=false` and an explicit persisted directory. Jaeger 1.76 documents Badger as embedded local storage, normally temporary unless configured otherwise; it does not represent a replicated distributed backend. Record initial/final allocated and logical sizes and write-I/O counters, retaining compaction/preallocation limitations. [Official Jaeger 1.76 deployment and storage documentation](https://www.jaegertracing.io/docs/1.76/deployment/).
- Use equal fresh/prewarmed backend conditions, or explicitly model a continuing database. Fresh-store growth and steady-state retained capacity are different measurements. Instrumentation added only to archive experimental receipts can itself add measurable work; include or separately account for it consistently.

## Probe correction and artifact acceptance

The existing late probe sets every non-database span's status to OK while delaying the error database leaf. Correct its description as delayed delivery of the sole remaining visible error marker. To isolate timing, compare immediate and delayed delivery of an identical leaf-only-error corpus. Add root-error-present variants as separate controls; do not change marker placement within the timing comparison. Preserve the original probe results and correct their interpretation instead of rewriting their history.

For each new cell, independently validate raw before/after metrics, the full unique request/incident universe, input/output span identities, parent links, and actual stored/retrievable traces. The validator should not simply import the experiment's diagnosis predicate. Verify classifier outputs with an independent truth scorer after classification. Persist exact CPU endpoints and executed-source hashes. Report transport failures, overload and incomplete traces as outcomes when they are intentional treatments; reserve cell invalidation for prespecified execution failures, and retain those failed receipts.

After these changes, the defensible contribution is an explicit mathematical evidence contract plus a reproducible empirical study of a fixed automated fault-localization endpoint and measured stack resources. It will not prove a universal safe discard percentage, production MTTR, human diagnosis, or commercial infrastructure savings.

## Bounded re-review during the frozen live run

Date: 2026-09-24, after source freeze and while the 60-cell run was active. Read the revised `paper/theory.tex`, `paper/methods.tex`, `docs/revision-20260924/protocol.md`, `amendments.md`, `experiments/revision/diagnose.py`, and `counterfactual.py`. No experiment, protocol, or manuscript was modified. This section reviews the stated analysis and source semantics; it does not certify completed run outcomes.

### Confirmed corrections and formal scope

The trace universe is now explicitly nonempty, and the singleton bound explicitly requires N>=1. The independent-sampling impossibility now varies the finite population size and distinguishes that claim from a fixed-N assertion. These corrections resolve the population-domain issue. The general model already defines p in [0,1], so the later reference to p<1 is properly interpreted within that domain.

The fixed-classifier proposition is correct. For a nonempty fixed failing-request set F, per-request classification, abstention on absent traces, and unchanged whole-trace contents, a retained request contributes its fixed full-trace correctness indicator q_i and an omitted request contributes zero. Consequently A(S)=sum(q_i I_i)/|F| and E[A]=sum(q_i pi_i)/|F|. Linearity requires no independence; the group recovery expression additionally requires independent inclusion. If no request in a group is diagnosable, its recovery is zero; this degenerate case can be stated explicitly instead of invoking a theorem whose displayed witness domain assumes m>=1.

The implementation matches this restriction: `diagnose.py` operates on one span list and returns a mechanism/service or abstention. `counterfactual.py` first computes each full-trace prediction, then reuses it unchanged only for retained trace IDs. Its group outcome is the logical OR of correct per-request predictions, with groups fixed before selection. Thus per-request and group loss relative to that same corpus is nonnegative and at most one. The proposition does not assume the classifier is correct. Its content-stability condition is properly restricted to offline selection, because online policies can alter execution timing and therefore classifier inputs. The partial-span ablations are separate interventions and are not covered by this monotonicity argument.

Adding nonnegative A_H and A_T to the cost models removes the implicit free-head-decision assumption. Both savings expressions follow correctly by subtraction. They remain conditional accounting models, not decompositions empirically identified by the live CPU totals. In particular, unchanged business work and linear scaling of avoidable telemetry work are modeling assumptions. The methods now correctly distinguish measured pipeline CPU, file-mirror overhead, PostgreSQL cgroup work, post-ingestion query work, close-time compaction, and storage receipts that include warmup.

### Simultaneous Hoeffding inference

For comparison ell define mu_ell=(1/n)sum_s E[L_s,ell], with independent block losses in [0,1]. Applying the bounded-variable inequality to negative centered losses gives Pr(mu_ell - mean(L_ell) > epsilon) <= exp(-2n epsilon^2). The union bound across at most M comparisons gives the displayed radius sqrt(log(M/.05)/(2n)). Truncation at one remains valid because mu_ell<=1. No independence is required between different comparisons, rates, or endpoints. A common future-block mean additionally requires the block distributions to represent the same target population; independence alone only gives the average of their expectations. [Hoeffding 1963, original publication](https://www.tandfonline.com/doi/abs/10.1080/01621459.1963.10500830).

The formula is therefore valid under its stated independent-block model. Independence is an assumption, not something guaranteed by distinct deterministic seeds, pseudorandom hashes, or resetting processes on a shared host. The bound must remain conditional on that assumption and must not be described as production-population coverage.

**Action needed in reporting:** with n=5 and M=160, the additive radius is **0.8983822176**. Since every offline loss is nonnegative, even zero observed loss produces an upper bound of at least 0.8984. Therefore **this prespecified bound cannot certify any sampled rate at the five-percentage-point margin**, regardless of the observed five-block outcomes. “Low precision” understates this mathematical impossibility. Full-retention equality is an exact deterministic control and can be reported separately, as the amendment already specifies. Do not replace the bound after seeing results. For scale only, this particular Hoeffding formula would require at least 1,615 independent blocks to make its radius <=.05 even at zero observed loss; this is not a recommendation to run that many blocks or a claim that every valid method needs that sample size.

The family count 160 is correct for 2 native policies x 10 rates x 4 application/load combinations x 2 aggregate endpoints. It does not cover cause-specific certification, shared-priority controls, ablations, online treatment differences, or any new endpoint. Such results may be descriptive, but must not inherit the family's coverage claim. The methods should explicitly define each block loss denominator and this aggregate-family restriction.

### Guards for the analysis and final claims

1. **Require all five blocks for a certified comparison.** `counterfactual.py` flags tail feasibility separately in each block. If any prespecified block is infeasible at a rate, do not drop it and analyze the remainder with n=5. Report the rate infeasible for that comparison, or retain it as an explicitly different descriptive question. A varying realized protected fraction is a substantive result.
2. **Keep online and offline budgets distinct.** The online tail rule uses the frozen .08/.98 background; the offline rule recalculates background from that full corpus's observed protected fraction. These are intentionally different policies when the fraction differs from .02. The revised methods disclose the difference and must preserve it in tables and conclusions.
3. **Do not turn an empirical grid crossing into certification.** Report the maximum tested rate/discard level meeting a point-estimate criterion only as descriptive. A discrete grid does not identify a continuous threshold, and the bound above provides no nontrivial margin certification here.
4. **Validate full-corpus inputs before offline analysis.** The parser uses a default empty span list for an absent ID. The fixed-content identity still holds for the observed corpus, but claims about complete full traces require the separate archive checks to pass for every offered baseline request. Missing full evidence cannot be silently removed.
5. **Check the finite native FNV boundary independently.** Offline code uses `int(bg*(2**64-1))`. Exact Go implementation arithmetic can differ at the final integer boundary if percentage multiplication/division is ordered differently. Validate identical choices for the actual IDs, including distance from any rounding boundary, rather than asserting unconditional byte-for-byte equivalence from the formula alone. This is a verification obligation, not evidence of an observed mismatch.
6. **Do not infer general service localization.** The classifier intentionally maps the recorded SQL mechanism or latency leaf to PostgreSQL and a domain leaf to its instrumented owner. Its accuracy supports this predefined task on these applications; it does not discover an arbitrary causal service from a production graph. The revised wording already largely respects this distinction.

No finding here requires stopping or modifying the active frozen experiment. The main required correction is explicit acknowledgment of zero certification capability for the chosen five-block simultaneous bound, plus precise labeling of its target and comparison family. The experimental estimates can still be informative and publishable within their stated scope even when the stronger margin guarantee is not established.
